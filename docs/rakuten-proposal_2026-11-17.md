## 3. 企画案（3案）

## 4. 必要な変更（サイトの仕組み：最小案）

今の広告リンクは、`[[aff:案件ID|文言]]` → サイト内の中継ページ（go/案件ID.html）→ A8 という流れで、リンクに `rel="sponsored"` とクリック計測（onclick）を付けている。**楽天では、生成されたHTMLへの属性の追加・変更が禁止なので、この方式をそのまま使えない。**中継ページも直接の記載はないが、「楽天市場だと分からない形」に当たるおそれがあるため使わない。

**最小変更案（12/16に始めると決めてから実装）**
1. 楽天で作ったリンクのHTMLを、1商品1ファイルとしてそのまま保存する（例：`data/rakuten/lan-adapter-1.html`。中身は一切変えない）
2. 記事には `[[rakuten:lan-adapter-1]]` と書く。build.py がこれを、保存したHTMLで**そのまま**置き換え、外側を `<div class="rakuten-link" data-program="rakuten" data-item="lan-adapter-1">` で囲む（楽天のタグ自体には触らない）
3. クリック計測は、ページ全体で1つのスクリプトが「`.rakuten-link` の中のリンクが押された」ことを検知して、GA4に `affiliate_click`（program_id=rakuten、article=記事名、item=商品名）を送る。楽天のタグに onclick を足さない
4. 週次計測（metrics.py）は今の `affiliate_click` の集計で、そのまま案件別・記事別に分かれる（program_id と article が同じ形で入るため）。楽天の管理画面の成果は、運営者が手で数字を写す（A8と同じ）
5. 法令チェック（compliance）に「楽天リンクの記事は冒頭のPR表記があるか」「楽天タグが保存ファイルと完全に同じか」の確認を足す
6. 楽天の商品紹介の直前にも「※ここからは、当サイトが提携している広告（アフィリエイト）の紹介です。」を入れる（今の決まりと同じ）

- 変更は build.py と compliance のみ。小さめのPR1本
- しないこと：リンクURLへのUTMやパラメータの追加、短縮URL、中継ページ、画像の加工、楽天の価格の書き写し（価格は変わるため本文には書かない）
